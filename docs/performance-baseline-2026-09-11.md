2026-09-11, Minecraft 1.20.4, BBS 2.3.1, IRLite/core 1.1.5,
ComplementaryReimagined_r5.8.1_IRLights, NVIDIA RTX 4080 SUPER.
Пользователь подтвердил: модели полностью неподвижны, включая анимацию/кости.
На скриншоте сетка моделей; профайлер показывает 26 загруженных источников.
Точное количество BBS-моделей отдельно не подсчитывалось.

## Доставка и ограничения

В runtime `irisFallback=false`. Хеш реально доступного ресурса ShadowBaker.class
совпал с классом в используемом named remap-JAR:
`e4ec5781ed546f178d399873bbf51b861c8f70c5c95b817970acb06d53743684`.
Полные source-хеши fullscreen-программ находятся в `run/runclient-console.log`.
Подробные GPU-таймеры и CSV были включены, VL sweep выключен.

В сохранённой при выходе конфигурации: shadow_quality=3 (ULTRA), partial_tile=true,
global vl_intensity=1.0, enableVsync=true, maxFps=260, renderDistance=12.
В стартовом JSON сессии ещё shadow_quality=1 (MEDIUM): пользователь менял настройки
во время подготовки сцены. Стартовый JSON не следует выдавать за настройки позднего
окна. VL-pass стоит около 0,09 мс, но это не доказательство global VL=0.
Стартовое разрешение framebuffer — 2560×1361; оно не записывалось каждый кадр.

Для контрольного A/B отключить VSync, зафиксировать настройки VL, оставить
26 источников и ту же сцену/камеру/разрешение/качество, начать новую сессию профайлера
после установки параметров. Затем отдельно сравнить анимацию одной модели и всех
моделей при фиксированных источниках. Модельный тип и способ оценки поз BBS должны
быть изучены до реализации версии силуэта: пользовательское «неподвижно» не заменяет
технический контракт invalidation для других сцен.

Уточнение VL-аудита 2026-09-11: прежний совет поставить global intensity=0
не отключает GPU-марш (Java ограничивает значение снизу 1e-6, GLSL применяет
интенсивность после марша). Для отдельного замера bake без VL выключать
IRLITE_VOLUMETRIC в shaderpack; для A/B самого VL сохранять ненулевую
интенсивность и одинаковые эффекты в обоих вариантах.

Клиент штатно закрыт пользователем; Gradle завершился с кодом 0. Последняя CSV-строка
обрезана буферизацией при выходе, как предусмотрено ограничением этапа 0; выбранное
окно целиком находится раньше неё, и все 600 `gpu-complete` присутствуют.
