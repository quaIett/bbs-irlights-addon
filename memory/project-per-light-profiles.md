СТАТУС 2026-09-16: struct-реализация профилей (всё ниже про SSBO 160 Б / core 1.1.7 / GLSL 7 паков) СПИСАНА и ОТКАЧЕНА из дерева — заменяется портом готового пакета v2 с другой машины, см. [[plan-port-perlight-v2]]. Из этой работы ЖИВЫ: оформление треков (TrackCatalogMixin + LightTrackLayout, раздел ОФОРМЛЕНИЕ ТРЕКОВ) и знания о BBS 2.6 API (треки, видимость Value, keyframe-события). Остальное — история и справка по граблям.

ЧТО ЭТО. В свойствах Point light / Spotlight две новые секции с мастер-тумблерами: «Own outline settings» (custom_outline) и «Own volumetric settings» (custom_vl). Тумблер OFF (дефолт) = источник живёт на глобальных настройках IRLights как раньше; ON = у источника свои ручки, и они же становятся треками реплея. Только look-ручки, зеркалят глобальные 1:1; quality-ручки (VL steps/strides, outline pixel size) намеренно остались глобальными.

ПОЛЯ ФОРМЫ (класс qualet.irlite.forms.LightProfileValues, общий для обеих форм, поле `profile`): outline(on), outline_target(0/1/2), outline_strength[0..3], outline_fresnel_power[1..4], outline_back[0..2], outline_front(bool)+outline_front_strength[0..1.5], outline_glow(bool)+outline_glow_strength[0..0.75]; vl_max_dist[1..256], vl_tip_boost[0..4], vl_tip_radius[0.1..8], vl_noise(bool), vl_noise_amount[0..1], vl_noise_scale[0.25..8], vl_shadows(bool).

ТРЕКИ РЕПЛЕЯ — механизм: ручки половины с тумблером OFF переопределяют `isVisible()` (анонимные подклассы Value*, гейт на тумблер). BBS перечисляет треки (TrackCatalog.properties) и создаёт новые (FormProperties.create) ТОЛЬКО для видимых свойств → треки появляются при включении тумблера. Загрузка сохранённых треков (readTracks) и apply видимость НЕ проверяют → сохранённые ключи скрытых ручек переживают файл и продолжают применяться (просто не влияют, пока тумблер OFF). Каталог перестраивается при setReplay/выходе из редактора формы.

ОФОРМЛЕНИЕ ТРЕКОВ (09-16, по запросу юзера: названия, цвета, группы): TrackCatalogMixin (RETURN TrackCatalog.of(Form, FormProperties)) -> LightTrackLayout.decorate(list): для PROPERTY-треков наших форм подменяет TrackDescriptor (title = читаемое имя, цвет/иконка по семейству) и подвешивает под вставленные header-дескрипторы kind=BODY_PART (ключ `<formPath>/irlights.<group>`, канал throwaway KeyframeChannel FLOAT — header не сохраняется, сворачивается/разворачивается как per-limb, prune убирает пустой). Группы зеркалят секции панели: Light / Volumetric beam / Shadows / Affects / Cookie / Outline (this light) / Volumetric (this light); у вложенного источника группы под строкой его body part. Цветовые семьи: оранж (Light), циан (beam), пурпур (Shadows), розовый/амбер (Affects), зелёный (Cookie), жёлтый (outline own), сине-бирюзовый (VL own). ГОТЧА: UIReplaysEditor.getColor больше не источник цвета для треков формы (TrackCatalog берёт TrackStyle.color напрямую) — старый UIReplaysEditorColorMixin был мёртвым и удалён; глобально перекрасить общие ключи ("color", "shadows") через TrackStyle.register нельзя без затрагивания чужих форм, поэтому окраска per-form в миксине.

ОТКАЧЕНО 09-16: маски «entities/blocks» (light_mask/outline_mask, свой keyframe-тип, cone.z=3, outlineA биты 4-5 always) — юзер имел в виду ДРУГОЕ: мульти-выбор КОНКРЕТНЫХ РЕПЛЕЕВ, на которые падает свет/аутлайн («источник задевает только выбранные реплеи»). Откат полный (Java, ядро, GLSL через backup+edit_glsl.py, патчи регенерированы); entities_only/blocks_only и outline_target как были. Per-replay targeting = новая задача: шейдеру нужен per-pixel ID реплея (gbuffer-канал с entityId/стенсил), в SSBO — битовая маска/список ID у источника; см. [[project-per-light-profiles]] хвосты.

UI: UILightProfileEditor (client/ui/.../panels) — виджеты для обеих панелей; тело секции = UIElement.column().stretch().vertical().height(20), скрывается setVisible(false) при тумблере OFF (резайзеры BBS пропускают скрытых детей). Target — UICirculate с 3 лейблами.

ДАННЫЕ -> GPU: LightFormProfiles.of(profile) (client/light) заполняет статический scratch org.qualet.irl.light.LightProfile (новый класс core) и передаёт в новые перегрузки LightRegistry.registerPoint/registerSpot(..., LightProfile, identity); старые перегрузки делегируют с null (редактор IRL-redactor не трогали). Registry копирует 12 полей в массивы, flush пакует их и считает header customFlags: bit0 = среди УПАКОВАННЫХ источников есть custom+enabled outline, bit1 = есть custom VL.

КОНТРАКТ SSBO v2 (IrlPatch.CONTRACT_VERSION=2, все 7 патчей `@irlite 2`; irl-core 1.1.7): struct 10×vec4 = 160 Б (было 96): +outlineA (x flags int-valued: bit0 custom, bit1 on, bit2 front, bit3 glow, bits4-5 target; y strength, z fresnelPower, w back), outlineB (x frontStrength, y glowStrength, zw reserved), vlCustomA (x flags: bit0 custom, bit1 noise, bit2 shadows; y maxDist, z tipBoost, w tipRadius), vlCustomB (x noiseAmount, y noiseScale, zw reserved). Header offset 12 `irlite_pad2` -> `irlite_customFlagsRt`. Флаги едут как float, читаются int(x+0.5). Детали: [[addon-light-buffer-ssbo]].

GLSL (все 7 Modification-либ правились скриптом scratchpad edit_glsl.py, построчно с сохранением EOL; VL-марш во всех 7 идентичен, аутлайн — 5 CR-семейства идентичен, Photon/IterationRP внутри irlite_lightSurface):
- VL: per-light lMaxDist/lTipBoost/lTipR2/lNoiseOn/lNoiseAmount/lNoiseScale/lShadowsOn, дефолт = глобалы; тумблеры только СУЖАЮТ глобальные (AND). irlite_vlNoise получила (scale, pOff): morph-оффсет теперь в noise-space (×4.0 периода) и добавляется ПОСЛЕ деления — целые периоды при любом per-light scale.
- Outline CR-семейства: irlite_outlineInk(playerPos, n, bool isEntity); маска глубины `edge` считается ЛЕНИВО первым источником, который дошёл до неё (без custom-источников — как раньше, спереди, с ранним выходом); при anyCustom (header bit0) глобальные enable/target применяются per-light внутри цикла, а композит пропускает пиксельный гейт и всегда считает isEntity. Композиты 5 паков: irliteOCustom/irliteOEntity объявлены перед гейтом, вызов ink с 3-м аргументом.
- Photon/IterationRP: irliteOGlobalHit + irliteOCustom, irlOEdge лениво в цикле, ранний return `!irliteODraw`.
