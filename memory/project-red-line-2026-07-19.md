Директива юзера (2026-07-19, сессия стресс-теста 500 источников), дословно: «с этого момента все изменения начиная с этого переходят красную линию, из-за того что у нас заканчиваются идеи и мы не можем…» — фраза оборвана, хвост «мы не можем…» НЕ уточнён (спрошено, ответа пока нет).

Контекст линии: расследование 9 агентов ПОДТВЕРДИЛО потолок кластер-маски MASK_LIGHTS=64 (ClusterGridBuffer.java:47; GLSL-хвост i>=64 немаскирован, читает 96Б struct до ранних выходов; 0.068-0.085 ms/источник на RTX 3060; sky-look тест юзера PASS = фрагментный цикл gbuffers). Спавн-логика исключена замером (кап-минимум при поле ON = 4.8 ms кадр). H2 «маска не работала» опровергнута. Попутные находки: BEAM_BONUS=64 вырождает приоритет реальных beam-ламп в ~70 блоках (продакшн-баг селекции, не чинился); outline в паке CR enabled-by-default вопреки канону; спайки 116-146 ms не атрибутированы (GC?).

**Why:** дальше идут рычаги без гарантии результата (P5 fetch-reorder GLSL, P8 census uploadedCount, потом возможно расширение маски uvec4/пер-тайл списки = слом контракта binding 6 + тираж 7 паков). Юзер хочет явную границу «проверенное/экспериментальное».

**How to apply:**
- ДО линии (обычный режим): стресс-кнопка 500, cpu-телеметрия профайлера ([irlite] cpu:), лог stress ON/OFF, тумблер shader_light_clustering, фикс bm=0 в StressTestLights.
- ПОСЛЕ линии (экспериментальное, маркировать в отчётах, НЕ коммитить без явного чекпоинта, держать откатываемым): P5 fetch-reorder — правится ТОЛЬКО установленная копия run/shaderpacks/ComplementaryReimagined_IRLights, НЕ Shadres и НЕ .irlights до вердикта; P8 — геттер uploadedCount в core LightRegistry + печать в cpu-строку; всё дальнейшее по маске/спискам.
- Решение о редизайне гейтится ДВУМЯ числами: P5 (сколько ms/light возвращает reorder) и P8 (превышают ли реальные сцены 64 залитых). Не коммититься в пер-тайл списки до обоих чисел.

**СТАТУС 2026-07-20: ЛИНИЯ ЗАКРЫТА — всё нижеперечисленное ЗАКОММИЧЕНО.** W2 (широкая маска + getUploadedCount) = core **b18a0c1**, инструментарий стресса/тумблер/cpu-телеметрия = addon **da92b7f**. Рантайм-гейт юзера PASS (2-й прогон, лог run/runclient-console.log): кап опускался ниже спроса (uploaded 25→5→1 — ветка отбора реально исполнялась), ULTRA-кламп сработал (`face size 4096 needs 6527 MiB > chain budget 3574 MiB; clamped to 2048`), free 7.1/12.3 GB, эвикции замерли (+0), исключений от нашего кода ноль; визуал юзер принял.

**BEAM_BONUS-баг ПОЧИНЕН** (core **1116b7c**): `buildOrder` клампил счёт в ноль ПОСЛЕ скидок → все beam-лампы ближе 64 блоков (72 с гистерезисом) получали score ровно 0 и разваливались в tie-break по id (identityHashCode) — при спросе>капа отбор шёл по хешу вместо расстояния. Фикс = убрать второй кламп, разрешить отрицательные счёта (priorityScore — ЧИСТО ключ сортировки, наружу не торчит: только buildOrder/precedes). Побочно ожил HYSTERESIS в ближней зоне (раньше −8 у лампы вплотную клампился обратно в 0). Гейт: опустить max_shader_lights ниже числа ламп в сцене — иначе ветка не исполняется вообще (первый прогон 2026-07-20 дал ложное «всё норм» при uploaded 25/cap 64).

**ИТОГИ ЗАМЕРОВ (2026-07-19, замерялось за линией):**
- Арка на стрессе-500: ~40 ms (старт) → 25.8 (P5 fetch-reorder: posRadius-first + readonly restrict b7) → 10-20 (W2 широкая маска, плотное поле 72×72) → ~10 ms медиана / 17-18 худший ракурс (разреженное поле 120×120, radius 3, intensity 3). 26 FPS → ~100 FPS.
- A/B тумблera clustering при 500: OFF = 25-32 ms, ON = 10-18 ms → широкая маска экономит ×2.5-3; ревью W2 (3 линзы) = 0 блокеров, фиксы применены (ceil WIDE_WORDS, кэш IntBuffer-view, javadoc-контракт).
- P8 census: реальные сцены юзера = 30-51 uploaded (< 64) — потолок был виден только в стрессе. Шаг 2 (per-tile списки) признан НЕ НУЖНЫМ: W2 достиг ~85% их выигрыша, худший ракурс (горизонт-полоса тайлов) списками не лечится (только depth-slicing — не открывать без нужды).
- Хвосты до тиража: GLSL-фолбэк «новый пак + старый мод» на легаси-маску (в пилоте невозможен, решить при тираже); пересборка редактора ОБЯЗАТЕЛЬНА (core «1.2» в mavenLocal неотличим от пре-W2; старый JiJ-core без getUploadedCount уронит профайлер аддона); BEAM_BONUS-баг селекции beam-ламп при спросе>капа — не чинился.
