Разобрано 2026-08-10 при попытке пресета «16px + поднять кап». Пресет 16px был сделан и **откачен пользователем** (не понравился визуально); знание ниже от этого не устарело.

**Разрешение (tileSize) НЕ зашито в GLSL.** Патчи берут каждый размер из `textureSize()` и адресуют тайлы в ДОЛЯХ атласа (`0.25`, `0.5`, `1.0/3.0`). Любой пресет разрешения = правка только Java (`IRLShadowQuality` + диапазон UI-настройки), ноль правок шейдеров, ноль перегенераций паков.

**Кап (сколько ламп разом держат тень) зашит намертво.** `SpotlightDepthAtlas.TIER_CELLS {8,6,2}` = 64 тайла, `PointDepthAtlas.TIER_SUPERCELLS {2,3,1}` = 30 блоков; продублированы константами `IRL_PT_END0/END1/CELL1/CELL2`, `IRL_SPOT_END0/END1/CELL1/CELL2` в патчах 7 паков × 2 мода (+ DOF-комбо) — «FROZEN MIRROR CONTRACT» в javadoc обоих атласов. Смена = ABI-брейк со всеми патчами.

**Жёсткий потолок 64 тайла на атлас** — dirty-маски типа `long`, гард в static-init обоих атласов кидает при `tileCount() > 64`. Spot УЖЕ на 64 — расти физически некуда. Point 30 → максимум ~60 (напр. `{0,3,3}`), и только ценой ABI-брейка.

Следствие, которое каждый раз кажется контринтуитивным: **«уменьшили разрешение в 64 раза → дадим в 64 раза больше теней» не работает.** Мелкий шрифт не добавляет строк в бланке. При T=16 VRAM ~0.25 МБ на обе цепочки против ~480 МБ у MEDIUM, и «догнать medium по VRAM» большим капом невозможно — клеток не станет в 500 раз больше.

Смежное: `softness=0` НЕ даёт жёсткий край — в GLSL `hard` включает только `IRLITE_SHADOW_QUALITY == 0` (опция шейдерпака в меню Iris, «Hard»/«Жёсткие»), а PCSS держит texel-floor `max(lightSize*worldToNdc, 1.5*texelNdc)`. Плюс билинейная кайма 2×2 в `irlite_spotGatherTap`/`irlite_pointGatherTap` — убрать = правка GLSL всех паков.

Границы разрешения снизу: ладдер ломается ниже T=8 (глубокий тир T>>2, фильтр-база `face/2` уходит в 0 → нелегальный `glTexStorage3D`). Клампы `setTileSize` (`while (size > 256 …)`) малые значения не трогают.
